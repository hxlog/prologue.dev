# AGENTS.md

This file provides guidance to Codex (Codex.ai/code) when working with code in this repository.

## What this repo is

A content-first personal blog (Chinese, `prologue.dev`) built on **Next.js 16 App Router + Turbopack, React 19, Tailwind CSS v4**, on an **in-repo filesystem content layer** (no Contentlayer). It doubles as the **source of truth for a public starter template** — see the "Template publishing" section, which is the least obvious part of this codebase.

## Commands

```bash
corepack enable        # once per machine — makes `yarn` resolve to the pinned Yarn 4
yarn install           # install dependencies (node-modules linker)

yarn dev               # build search index + next dev --turbopack
yarn build             # same prep, then next build --turbopack
yarn start             # serve production build
yarn lint              # eslint (flat config in eslint.config.mjs)

yarn build:e2e       # testing-API-enabled production build for Playwright
yarn test:e2e        # instant navigation + SEO + overlay e2e

yarn publish           # build the template snapshot locally (dry run — no push)
yarn publish -- --push # force-push template to hxlog/prologue-blog-template
```

CI (`.github/workflows/ci.yml`) runs `lint`, `build`, and the production-mode `e2e` job.

## Package manager

**Yarn 4 (Berry)**, pinned by `packageManager` in `package.json` and driven through Corepack: run `corepack enable` once per machine, after which `yarn` resolves to the pinned release anywhere in this repo. `yarn.lock` is committed; there is no `package-lock.json`. `.yarnrc.yml` sets `nodeLinker: node-modules` — Next.js/Turbopack and Vercel both need a real `node_modules` tree, so Plug'n'Play is not an option here.

CI enables Corepack before every job and installs with `yarn install --immutable`, which fails instead of rewriting `yarn.lock` (the `npm ci` equivalent). `engines.node` is `24.x` (the Vercel-supported LTS line; `engines` overrides the dashboard setting), `.nvmrc` is `24`, and CI uses `24.x`.

Two dependencies are deliberately not on `latest`, both because of peer ranges rather than preference:

- **`eslint` on the latest 9.x** — `eslint-config-next@16` pulls in `eslint-plugin-import`, `eslint-plugin-react` and `eslint-plugin-jsx-a11y`, whose peer ranges stop at `^9`. ESLint 10 is a real peer conflict there (npm fails with `ERESOLVE`), so 9.x is the conflict-free latest.
- **`typescript` on the latest 6.0.x** — `eslint-config-next` imports `typescript-eslint`, which `require`s `typescript` at lint time even in a JavaScript project, so it is a real devDependency (npm used to install it as a transitive peer; Yarn does not). Its peer range is `>=4.8.4 <6.1.0`, and TypeScript 7 is out but unsupported.

Everything else is on `latest` as of the migration. `yarn up -i` is the interactive upgrader; `yarn up tailwindcss @tailwindcss/postcss` picks up the one patch release that Yarn's default 24-hour `npmMinimalAgeGate` (supply-chain quarantine of freshly published versions) held back.

## Content layer

There is **no Contentlayer**. `src/lib/content/` reads `data/content/**` with `fs` and produces the same document shape Contentlayer2 emitted:

- `load.js` — the loader. Reads frontmatter, computes `readingTime`/`headings` eagerly; `body.html` is **lazy and async** (Shiki is the whole cost). `getPosts()`, `getPages()`, `getPost()`, `getPage()`, `getBodyHtml(doc)`, `getAllPostsWithBody()`.
- `pipeline.js` — the one markdown renderer (unified: remark gfm/math/gemoji → rehype katex/slug/figure/mermaid-pre/shiki/stringify). Plugin order and options are copied from the old `contentlayer.config.js` and verified byte-identical against it. **Do not add options to `remarkRehype` or `rehypeStringify`** — Contentlayer called both bare, and raw HTML blocks collapsing to their text content is load-bearing for three posts.
- `slug.js` — the slugger + heading extractor (F2 fix: anchors and ids now come from the same pass).
- `index.js` — the public API, and **the only file carrying `import "server-only"`**. `standalone.js` is the same surface without the guard, for plain `node scripts/…`.

**The exports are functions, not arrays, and the name says so.** `getPosts()` replaces Contentlayer's `allPosts` constant. The markdown is read with `readFileSync`, which no bundler watches, so a module-scope constant freezes at first evaluation and a content edit in `next dev` keeps serving stale HTML. `load.js` therefore checks an mtime+size signature of the tree on each access (~1.2 ms over 64 files vs ~103 ms to re-parse) and re-reads when it changes; the check is skipped entirely under `NODE_ENV=production`. See `current()` in `load.js` for the ENOENT/EBUSY reasoning. Do not "simplify" this back into a constant, and do not cache the returned array across a render.

Frontmatter is validated **loudly**: a mistyped `draft: "false"` (which is what Obsidian's Properties UI writes when the property type is Text) fails the build naming the file and field, where Contentlayer2 warned and silently skipped the document. Pages (`data/content/pages/`) need only `title` and `description`; posts also need `publishDate`. **A page's body is plain markdown and raw HTML in it is dropped, not escaped** — the pipeline calls `remarkRehype`/`rehypeStringify` bare, so an `<img class="...">` in `about.md` disappears. Anything on a page that needs styling, like the author avatar, is a frontmatter field the page template renders (`avatar:`, opt-in); see `docs/CONTENT.md`.

`src/lib/microblog.js` reads the one non-post dataset: `data/microblog.yaml`, a list of `{ date, content }` entries. It parses with the `yaml` package and returns `getMicroblog()`. Entry ids are **derived, not stored** — `mb-<YYYYMMDD>-<array index>` — so they are stable only as long as the list order is; inserting an entry in the middle renumbers every later one and breaks `/microblog#…` anchors and RSS guids at once. `getMicroblog()` is a function for the same staleness reason as the loader.

`data/links.yaml` (friend links) is read inline by `src/app/links/page.js` with the same parser. `data/static/` no longer exists: the site's static assets are a **real tracked directory** at `public/static/**`, served directly by Next at `/static/*`. It is deliberately not a symlink or junction to a directory under `data/` — Next's static-copy step refuses to copy a directory into itself, which fails the build on Vercel ("Cannot copy '../data/static' to a subdirectory of itself").

`data/sitemetadata.js` and `data/tagLabels.js` are **hand-written** modules, not generated. They are read by *client* components (navbar, footer, the two modals, tag chips), so their values have to be in the JS module graph and shipped to the browser — a browser cannot import markdown, and an `fs` read at render time cannot reach a Client Component either. That is why they are `.js` and why they are committed rather than gitignored.

`data/headerNavLinks.js` is a `.js` file for the same client-component reason.

`data/sitemetadata.js` is the single source for owner/site identity: title, author, description, avatar/cover, email/feed email, GitHub, optional Zhihu, license, feed generator, and the page-level copy under `pages` (archive, microblog, links, ui, llms). Runtime code reads these fields; optional social values such as `zhihu` are rendered only when defined. The public template uses generic values and an empty `zhihu`. Do not reintroduce owner-specific strings into `src/`; add a field to `data/sitemetadata.js` (and the matching `template/data/sitemetadata.js` when it is a starter setting) instead.

## Markdown pipeline & Mermaid

Configured in `src/lib/content/pipeline.js` (remark: gfm, math, gemoji; rehype: katex, slug, custom `rehype-figure`, custom `rehype-mermaid-pre`, shiki, stringify). The custom rehype plugins live in `src/components/`.

`rehype-mermaid-pre` converts ```mermaid code fences into `<pre class="mermaid">` blocks. Mermaid is then rendered **two different ways** depending on the consumer — keep both in sync if you touch either:

- **On the web**: `OptimizedHTMLRenderer` (`src/components/optimized-html-renderer.js`) parses the rendered HTML, routing `<img>` to `next/image` and `<pre class="mermaid">` to the client-side `MermaidBlock` (dynamic-imports `mermaid`, theme-aware, immediate on mount); everything else goes through `dangerouslySetInnerHTML`. `MermaidBlock` **replaces** the `<pre>` with a `div.mermaid`, so a rendered page has 0 fences and 1 SVG — anything asserting on fence count is asserting on what is supposed to be gone.
- **In feeds**: `src/lib/feed/mermaid.js` + `mermaid-shared.mjs` rewrites the same `<pre>` blocks into hosted `mermaid.ink` PNG `<img>` URLs (pako deflate + base64url encoding), since RSS readers strip inline SVG.

**The web renderer forces `look: "classic"`.** Mermaid 12 defaults `flowchart.look` to `"neo"`, which paints a `drop-shadow(1px 2px 2px rgba(185,185,185,1))` halo plus a gradient stroke around every node and cluster. Against the flat hairline surfaces that reads as duplicated elevation ("dirtier than GitHub"). `MermaidBlock` initializes with `look: "classic"` and passes `--font-sans` via `themeVariables.fontFamily`; `globals.css` keeps an `!important` `filter: none` reset over `.mermaid svg [data-look="neo"]` as a backstop. Measured: 0 elements with a computed filter across three diagrams, versus every node rect before.

## Feeds (RSS / Atom / JSON)

Routes: `src/app/rss`, `src/app/atomfeed`, `src/app/jsonfeed`. All three call `createFeed()` in `src/lib/feed/build-feed.js`, which builds a single `Feed` instance; each route only picks the serializer (`rss2`/`atom1`/`json1`). Per-item HTML is produced by `buildFeedContent()` in `src/lib/feed/content.js`, which promotes block math (`math[display="block"]`), absolutizes URLs, and normalizes images. The old KaTeX-stripping pass is gone now that formulas are native MathML. Format-specific fixes the `feed` library can't express (inject `<dc:creator>`, JSON Feed per-item `image`) live in `src/lib/feed/finalize.js` — note `imageByUrl()` is a function, not a module constant, for the same staleness reason as the loader. URL helpers in `src/lib/feed/urls.js` derive absolute URLs from `siteMetadata.siteUrl`; `coverImageUrl()` falls back to the `/og` generator when a post has no `image`.

Feed XML comes from `getFeedXml(format)` in `src/lib/feed/cached.js`, split at the cache boundary: `getFeedItems()` is `'use cache'` + `cacheLife({ stale: 600, revalidate: 600, expire: 604800 })` + `cacheTag("feeds")` and returns a serialisable item list built from `getCachedPost(slug)` — the article route's own `cacheLife("max")` entry — so the corpus is rendered once per deploy instead of once per format per hour (cold item build 140–390 ms, warm 8–13 ms, against 10–23 s before). `getFeedXml()` only assembles and serialises (6–19 ms) and must not read the clock; the routes stay `○`. `<lastBuildDate>` is `max(lastmod || publishDate)`, never `new Date()`: a render-time timestamp makes every regeneration write different bytes, which Vercel bills as an ISR write.

## Template publishing (important)

This repo is mirrored to a public template (`hxlog/prologue-blog-template`) **without the author's posts, maintainer-only files, or personal assets**. On every push to `master`, `.github/workflows/publish-template.yml` runs `yarn publish`, which executes `scripts/publish-template.mjs`. That script:

1. Creates a detached git worktree of `HEAD`.
2. `applyStarterTemplate()` deletes maintainer-only paths (`template/`, `docs/`, `.idea/`, `scripts/`, the publish workflows), wipes `data/content/*` and `public/static`, then copies the starter overrides from `template/`.
3. Force-pushes the snapshot to the template repo (auth via `TEMPLATE_REPO_TOKEN` secret, falling back to `gh auth token`).

**Implications when editing:**
- The `template/` directory is the starter's overrides — not used by this site, but *is* what template users receive. Edit it when you intend to change the template's default content/assets.
- Anything new added for the template must be placed under `template/` (or whitelisted in `applyStarterTemplate`), or it won't ship. `ensureTemplateInputs()` asserts the required ones exist, so a missing file fails the publish rather than shipping a broken clone.
- Template-critical files that live in `src/` or `scripts/` are copied explicitly by `applyStarterTemplate`: `scripts/build-search-index.mjs` — the only script the shipped `package.json` invokes. **Anything the shipped `dev`/`build` scripts invoke must be in that list**, or a fresh clone fails on its first command.
- `template/data/{microblog.yaml,links.yaml,sitemetadata.js,headerNavLinks.js,tagLabels.js}` and `template/public/static/` are required inputs; five `src/` files import the two `.js` data modules, so a template without them does not build.
- Locally, `yarn publish` builds and inspects the snapshot under `.tmp/` (gitignored) and stops; `yarn publish -- --push` is what force-pushes. CI passes `--push`.

## Design system

Semantic tokens live in `src/app/globals.css` under `@theme inline`, mapped to CSS variables that flip under `.dark`.

**Brand primitives: lavender `#b5b5e5`, pink `#e6c9d9`, warm stone `#a8a29e`** (`--color-brand-*`) are the historical source swatches and carry no semantics. The pastels actually painted are `--accent-pastel #c9cdf5` / `--secondary-pastel #f7d4e6` / `--sky #b4e0ec`. None carry text; everything reads a semantic token.

**v3 "ice lavender" palette.** v2 ("cool paper") moved the neutrals from warm stone to cool slate; v3 pushes the accent one step lighter, because the purple still read as heavy:

- **Light**: background `#f7f8fc`, ink `#2f3446` (11.6:1), surfaces `#ffffff` / `#f1f3fa` / `#e5e8f3`, `--muted #5d6579` (5.49:1), `--faint #767e92` (3.83:1, metadata only), accent `#6a6fcd` (**4.15:1** on the page, 4.40:1 on a white card), secondary `#b85680` (4.23:1). **The accent is deliberately below AA for small text, but only for chrome** — eyebrows, the active nav pill, card-title hover, tints. Body copy does not use it: prose links and inline code use `--accent-strong` / `--secondary-strong` (≥5:1), and any *fill carrying a label* uses `--accent-strong` too (5.35:1 with white). Link hover goes lighter, not darker.
- **Dark**: background `#14161d`, surfaces `#1c1f28` / `#242832` / `#2f3441`, ink `#eef0f7` (15.9:1), `--muted #b3b8c6` (9.1:1), `--faint #979db0` (6.7:1), accent `#ccd0f8`, secondary `#f4cede`. `--border-strong` is `0.14`, not `0.18` — the brighter hairline was half of the "dark hover is too white" report.
- **Sky `#b4e0ec`** (`--sky`) exists for gradients and the cursor glow only — never text, never a control, so it cannot fail contrast.
- `--accent-strong` means "more contrast against the current background" (darker in light mode, lighter in dark). `--on-accent` is white in light mode / `#1b1d26` in dark.
- Gradients: `--gradient-brand` is the **fill**, now **three stops** (lavender → `#dff0f9` sky → pink) so a brand rule reads as a gradient instead of a two-colour ramp; `--gradient-brand-text` is the **text** gradient (`bg-clip-text` must use it). **The homepage hero has no colour wash**: it sits directly on `--background` with no overlay layer (the old `.hero-aurora` gradient and `--gradient-aurora` token are gone — do not reintroduce a tinted layer behind the opening copy).
- Type (`--text-caption/sm/base/lead/title/h2/h1/display`), radii (`control/card/panel/pill`), containers, shadows and motion (`--duration-*`, `--ease-out-expo`) are tokens; prefer them over arbitrary values.

The v3-style `tailwind.config.js` (loaded via `@config`) holds only `darkMode: ["class"]` + the typography plugin.

**Fonts: system only — ZERO font requests.** No `next/font` import exists. `--font-sans` is the latin faces followed by the platform CJK stack and is the *only* family (`--font-serif` was deleted; its three `font-serif` call sites folded in). `--font-mono` is the platform mono, used only by code and `.copy-field`.

Two rounds got here by measurement: the two `Noto_*_SC` families (101 unicode-range slices each, **33 woff2 / 1.99 MB** on one article, every arriving slice repainting the text and minting a new LCP candidate — p75 13.2 s on a 196 KB page), then the last latin mono (`JetBrains_Mono`, 40 KB), whose `display: "swap"` still painted code in the fallback first on every code-heavy article. **The swap repaint is the mechanism, not the byte count** — do not reintroduce a webfont without re-measuring LCP.

There is no exception left. Formulas used to be the one non-text font: `katex.min.css` (imported by the post route) declares 20 `@font-face` rules, and the browser fetched the 1-3 math faces an article actually used (10-25 KB). `rehype-katex` now runs with `output: "mathml"`, the post route no longer imports the KaTeX stylesheet, and the site makes **zero font requests**. Measured on a 10-formula post: 0 woff2, 0 `span.katex-html`. The trade is formula fidelity — MathML is set by the platform math font, so glyphs differ per OS. Reverting means the plugin option plus the stylesheet import; keep the 0-font number as the baseline.

**Map the whole `--tw-prose-*` family.** `@tailwindcss/typography` only swaps its defaults under `.prose-invert`, and dark mode here is a class on `<html>` — its `--tw-prose-headings` (`#111827`) therefore painted every H1/H2 near-black on the dark background. The `.prose` block in `globals.css` points headings, bold, links, quotes, captions, bullets, code and table borders (plus their `-invert` twins) at semantic tokens; add new prose rules *after* that block.

**No animation library.** `framer-motion` was removed: the root `<MotionConfig>` alone pulled it into every route's shared chunk to honour an OS preference. Reduced motion is CSS; the tab cascade is `.reveal-rise`, the TOC marker is `.toc-pill`.

**Component classes** (in `@layer components`, `globals.css`): `.shell`, `.sticky-below-nav`, `.skip-link`, `.btn*`, `.input`, `.nav-item` (a pill), `.card` / `.card-interactive` / `.card-spotlight`, `.chip*`, `.eyebrow` / `.section-label` (not uppercase, not tracked — the labels are Chinese), `.link`, `.text-gradient`, `.glass-header`, `.reveal-rise`, `.toc-pill`, `.modal-panel`, `.copy-field`.

Cards are flat at rest: `--shadow-card` is an inset hairline ring (no themed drop shadow). Hover is a 2px lift plus **one twin-outline system** — `.card-spotlight::before` paints a 1px conic rim whose three colour sectors rotate to the pointer, `.card-spotlight::after` paints a soft pointer-tracked glow, and the second outline is a 1px inset hairline (`--glow-shadow`) over the neutral one:

- `conic-gradient` with three 120° sectors (sky, lavender, pink) and 6 % blends, masked to its 1px border by `content-box` + `mask-composite: exclude`. `from: calc(--spot-ang + 90deg)` puts the first sector boundary at the pointer; measured, centre hover (from 90°) → pink top / sky right+bottom / lavender left, and top-left hover (from -61°) → sky top / lavender right / pink bottom-left.
- The glow is two concentric radials at `--spot-x`/`--spot-y` (lavender core, sky halo) at 0.24/0.12 light and 0.07/0.033 dark — deliberately not a third hue, because a tri-hue glow blends to lavender under the text.
- Light hover: **mean L 0.967 vs 0.999 at rest, max C 0.090, 24 % of the card chromatic**. Dark hover: **mean L 0.275 vs 0.241** (+0.034) so it stays a faint halo. The real card's title colour is unchanged hovered vs rest in both themes.
- Replaced the v4 band wash + 1px rim + three-blob glow and the later conic "aurora" ring. `.card-ring`, `--aurora-*`, `--ring-*`, `--sheen-hi`, `spot-breathe` and `--spot-a` are gone; `--glow-*` are RGB triplets shared by rim, hairline and glow. Chip pills reuse the rim in a cheaper form ("stardust"): 6 % wash + 1px lavender hairline at rest, hover spins a 1px conic rim on the registered `--chip-ang` (5.5 s) and twinkles two 1px stars (1.7 s) while the label goes `--accent-strong`; `--chip-wash-a` / `--chip-ring-a` / `--chip-hairline-a`, and the old `--wash-*` fill is gone.

**Pointer-tracked cards**: `<Spotlight />` in `layout.js` (`spotlight.js`) — one delegated `pointermove` listener writes `--spot-x`/`--spot-y` percentages and `--spot-ang` degrees onto the hovered `.card-spotlight`; hover is pure CSS (`.card-interactive:hover::before/::after { opacity: 1 }`). It updates on **every** move inside a card (an early `card === current` guard froze the decoration at the edge), batches writes into one `requestAnimationFrame`, and caches the rect until scroll/resize. The `@property` registrations (`--spot-x/y` `<percentage>`, `inherits: true`) must stay **outside** `@layer components` or they are not emitted; with them the glow eases to the pointer (140 ms) instead of jumping, and the transition lives on `.card-spotlight::after` where the values are consumed. `--spot-ang` is intentionally unregistered — a conic gradient is 360°-periodic, so easing across the ±180° wrap would spin the rim. Pseudo-element layers are `z-index: -1` under `isolation: isolate` so the stretched link keeps working. No animation is left to disable under `prefers-reduced-motion`.

**Never write `-webkit-backdrop-filter` by hand** — Lightning CSS then drops the standard `backdrop-filter`, which silently killed the navbar blur. Declare only the unprefixed property.

**The living UI standard is `/ui`** (`src/app/ui/page.js` + `src/components/ui-standard/*` + `src/lib/css-probe.js`): it reads the palette, type ladder, radii, shadows and motion values out of the running stylesheet (CSSOM scopes for `:root` / `.dark` plus `getComputedStyle`) instead of copying them, so `globals.css` stays the only source of truth. A new token gets one row in the page's `GROUPS` arrays; a new component gets a specimen there before it ships anywhere else. Do not add a case-only `/UI → /ui` redirect — Next matches redirect sources case-insensitively, so the rule also matches `/ui` and loops.

Shared UI primitives: `card.js` (hairline ring + hover lift; used by home, `/blog`, `/tags/*`, related posts), `tag-chips.js` (responsive +N collapse, expand-in-place), `modal.js` (+ lazy `rss-modal-panel.js` / `email-modal-panel.js`, both copy-to-clipboard with manual-copy fallback), `post-grid.js` (archive load-more card grid), `search-dialog.js` (lightweight navbar trigger, state reset on every open) + `search-dialog-panel.js` (lazy-loaded server-search command palette); `rss-modal.js` / `email-modal.js` / `mobilenav.js` likewise keep only their triggers synchronous and load their panels on intent, with an idle-preload pass after first paint and a full focus/keyboard/animation implementation for the custom mobile menu, `portfolio.js` (server-rendered GitHub project cards for `/about`, fed by `data/projects.yaml` + `src/lib/projects.js`; uniform two-column cards with no featured slot and no arrow/action button — the whole card is the repository link; the section header is only the "Open source" eyebrow and the title, with no count/sort line). **Microblog timeline** (`microblog-timeline.js` + `microblog-entry.js`) is shared by `/microblog` and the home sidebar. Entries are grouped by Beijing year; the year label sits **before** the cards and each year owns a fresh 1px spine and node set. On the full feed the year label is sticky below the navbar until its section scrolls past; `compact` keeps it static so it cannot fight the home sidebar's own sticky container. Cards carry `.card-interactive` + `.card-spotlight` for the article-card hover decoration (2px lift, tri-hue rim, pointer glow), but text and empty space stay inert: only an image opens the article lightbox. The card carries only `Oct. 4` (month abbreviation, no zero-padded day, no year or sequence number); images keep the 1/2/3 grid with 10px gaps, a surface border and hairline shadow, and paging/caption are scoped to the clicked card via its `<article>`. `compact` changes the year rail, card padding, type, clamp and image gaps only. The list owns entry ids and `scroll-offset`. `ten-years-link.js` renders the official `https://www.foreverblog.cn/go.html` wormhole as a footer inline `.link` (F1) and a `/links` banner card (L1); the copy is exactly `十年之约 · 虫洞`.

Custom `.prose` overrides in globals.css must keep their `:not(.not-prose *)` guards or they leak into card UI.

**Theme toggle**: `themeswitch.js` wraps the swap in `document.startViewTransition` with a circular `clip-path` reveal (0.618 s) and adds `.theme-vt` for its duration. `clip-path` is not composited, so the smoothness comes from making the reveal the *only* animation running: `html.theme-vt * { transition: none !important }` suppresses every Tailwind `transition-colors`/`transition-all`, which would otherwise crossfade the same theme tokens underneath it. The block also drops the sticky navbar's `backdrop-filter`. `.theme-vt` is removed in `.then(ok, err)` (not `.finally()`-style success-only) so a rejected transition cannot leave it stuck and freeze every transition site-wide. Measured via `document.getAnimations()`: 0 CSSTransitions mid-reveal with the rule, 561 without.

**Route transitions**: every page wraps its content in `<RouteTransition>` (`src/components/route-transition.js`), a `react` `<ViewTransition exit="page-exit" enter="page-enter-fade" default="none">`. **Both halves are named, and both are animated from the view-transition snapshots, not from the live DOM.** That split is the point: an enter animation on the live tree only runs if React unmounts and remounts the element, and React reuses a node of the same type in the same position — so an exit can run with no matching entrance. A `::view-transition-new` snapshot is created for every transition that produces new content, so that half cannot be skipped. `.page-enter` remains, but as the **first-paint** fade only (a first paint is not a Transition and gets no snapshot); it is also what `PageTransition` emits, and `/blog/[...slug]/page.js` uses the class directly.

Timings are deliberately unequal — `::view-transition-old(.page-exit)` runs `page-fade` **150 ms** reversed, `::view-transition-new(.page-enter-fade)` runs `page-enter-snapshot` (opacity + a 6 px rise) for **260 ms**. Equal durations put both layers at ~50 % opacity at the midpoint, which reads as a wash; the shorter exit makes it a handoff. The 6 px transform is safe **only** on a snapshot pseudo-element — a transform on real DOM creates a containing block and would break `position: sticky` descendants (the homepage's pinned search bar), which is why `PageTransition` stays opacity-only.

CSS lives in `globals.css` next to the theme block. Two details there are load-bearing: `::view-transition { pointer-events: none }` (the snapshot overlays the live page and would eat the reader's next click), and `html:not(.theme-vt)::view-transition-old(root) { animation: none }` — the UA cross-fades the root on *every* view transition, which double-animates a route change; the theme toggle has its own root rule and so is excluded rather than overridden. The navbar and footer sit in `layout.js` *outside* `<main>`, so they are outside every page snapshot and hold still while the content crossfades — the nextjs.org arrangement. Measured with `document.getAnimations()` on `/blog` → post: one `page-fade` at 150 ms on `::view-transition-old`, one `page-enter-snapshot` at 260 ms on `::view-transition-new`, no `old(root)` fade.

**There is deliberately no `loading.js`.** Every route here is static and prefetched, so a navigation resolves in the same commit as the click and there is nothing to suspend on — the fallback could never legitimately show. Measured: adding one for `/blog` moved the real page into `<div hidden id="S:0">` behind JavaScript (+1.0 KB gz on `/blog`, +3.0 KB gz on a post page) with **no `<noscript>` fallback**, so a JS-less reader got skeletons instead of the article. The Next 16 docs agree it is the wrong tool twice over: `prefetching.md:59-62` says a route *with* a `loading.js` prefetches only "layout to first loading boundary" and its client cache TTL drops to "off by default", where a route without one prefetches the "entire page" for 5 minutes — so adding one would cancel the prefetch and then hide the round-trip it creates. Do not re-add one without re-measuring.

Tags: canonical slugs are English (15-tag taxonomy), Chinese display labels live in `data/tagLabels.js`. Tag URLs are `/tags/<EnglishSlug>`. Unknown tags (including the old `/tags/Web3`) are rejected by the generated proxy allowlist and return a hard 404; there are no legacy tag redirects.

## Rendering model (Cache Components)

`next.config.js` sets `cacheComponents: true` **and** `partialPrefetching: true` — the latter is *not* implied by the former: unset behaves like `false` and logs a warning (`node_modules/next/dist/docs/01-app/03-api-reference/05-config/01-next-config-js/partialPrefetching.md`). In Next 16 these change what a render may do:

- **No synchronous IO during prerender.** `new Date()`, `Math.random()`, `cookies()`/`headers()` throw with `blocking-prerender-current-time`. Wrap the read in `'use cache'` + `cacheLife()` instead of moving the page to request time — see `src/lib/site-year.js` (footer year, `cacheLife("max")`) and `sitemap.js`, which derives `lastModified` from frontmatter so it does not need a clock at all.
- **Request-bound work sits behind `<Suspense>`.** `layout.js` wraps the navbar's `NavList` (`nav-links.js`, a `usePathname` client component) so the static shell still prerenders. `Lightbox` reads no router state, so it mounts directly; its viewer chunk is imported on intent.
- **A page whose first statement is `await params` has no static shell.** Partial Prefetching renders one URL-independent App Shell per route, so awaiting `props.params` early fails `next build` with `blocking-prerender-dynamic` (or `instant-shell-url-data` at runtime). The three params routes are solved identically: a **non-async** route component renders the frame and passes the `params` *promise* down; an inner async component awaits it inside `<Suspense fallback={<ArticleSkeleton />}>`; content reads go through `src/lib/content/cached.js` (`'use cache'` + `cacheLife("max")`, keyed by slug) so the hole resolves as a cache read and Shiki never runs per request. They report `◐` — expected for a params route, and **not** a reason to use `export const instant = false`, which drops the prerender entirely.
- **`runtime` route segment config is rejected.** No `export const runtime = "edge"`; `/og` is Node-only because it reads the avatar from disk.
- Build table buckets: `○` static, `◐` partially prerendered, `ƒ` on demand. A route drifting to `ƒ` is usually an accident.
- DOM queries must be scoped (`main`, `main article`): React `<Activity>` keeps navigated-away routes mounted but hidden.

## Open Graph card

`src/app/og/route.js` draws a 1200×630 light-mode card with `next/og` (Satori). Everything the card depends on travels in the query string (`title`, `date`, `read`, `tags`), which is why `s-maxage=31536000, immutable` is safe; call sites build it with `URLSearchParams` (`src/lib/feed/urls.js`).

- Satori has no grid and no `filter: blur` — blooms are stacked radial gradients, and every element with children needs `display: "flex"`.
- The palette is duplicated in the file: Satori resolves inline styles outside the document and cannot read CSS custom properties. Keep it in sync with `:root`.
- Fonts and the avatar come from `assets/og/` (three Noto Sans SC subset TTFs + `glyphs.json` + a pre-scaled `avatar-152.png`, generated by the maintainer script `scripts/build-og-font.mjs`). Nothing is fetched at request time and `sharp` is no longer in the `/og` module graph — it used to cost 6 Google round-trips (195–790 ms) and a 58–134 ms resize per cold render. `outputFileTracingIncludes['/og']` must list `./assets/og/**`, or the deployed function falls back to remote fonts and an initial-letter avatar. A glyph the subset lacks still falls back to a per-card Google subset.
- Fonts are fetched per card as a Google Fonts `text=` subset of the exact glyphs drawn; a failed weight is dropped, not retried.
- Post cards carry date / reading time / 3 tags + `+N`; page cards drop those rows and centre the title. Both always show blog name, domain and author.
- **v4 visual language ("星屑边"):** three pastel blooms on the paper field; a white card inset 40 px inside a 2 px tri-hue rim (gradient box + 2 px padding, since Satori cannot mask a conic border); two 4–5 px star dots top-right; a gradient hairline above the footer; 40 px "stardust" tag chips with a 6 % tri-hue wash. The root needs explicit `width/height` numbers — percentage height resolves to content height and silently shrinks the card to its first block.

## Routing overview

- `/` — home (`src/app/page.js`): featured grid + Latest/top-tag tabs (client-side `Articles`, load-more in batches of 8) + about/microblog sidebar (the terminal / 随想 block is gone). Site-wide search is the navbar dialog, not a home tab.
- `/blog` — archive with tag sidebar and load-more (numbered pagination removed; old `/blog/page/*` paths fall through the proxy allowlist and return 404). Search is the navbar dialog.
- `/blog/[...slug]` — a post. Matches via `post.slugAsParams` against `getPosts()`; includes related posts (`lib/related.js`: tag overlap + recency, excludes prev/next) and a CSS scroll-driven reading-progress bar. The right rail pins the outline, not the author card: `AboutMe` is in normal flow and scrolls away, `.toc-panel` is the sticky element (a direct child of the `aside`; nested deeper its sticky range ends at the card's bottom) and caps itself at `100dvh - nav` with internal scroll.
- `/[...slug]` — markdown pages (e.g. `/about`, plain markdown, no JSX). Matches via `getPages()`. Pages with `portfolio: true` in frontmatter also render the GitHub project block after the body and before the comments. Because that block is a component and not markdown, the page outline appends a synthetic `开源项目` entry pointing at its `portfolio-title` heading (`scroll-offset` keeps the jump clear of the navbar).
- `/tags/[...slug]` — tag pages, **statically prerendered** via `generateStaticParams` from `lib/tag-counts.js`; same cards and load-more as `/blog`. `getTagCounts()`/`getSortedTags()` are functions, not constants, for the same staleness reason as the loader.
- `/microblog`, `/links` — microblog, friend links. `/microblog/rss` is a standalone RSS 2.0 feed for the microblog (full text + images via `content:encoded`, first image as enclosure).
- `/api/search` — server-only full-text search endpoint behind the navbar dialog. `ƒ` on demand, `private, no-store`.
- `/og` — Open Graph image, Node runtime, CDN-cached (see "Open Graph card" above).
- `sitemap.js`, `robots.js`, and the feed routes handle SEO/discovery; tag pages are listed in both. Retrieval-oriented AI agents are allowed explicitly in robots, training crawlers are asked not to train, and `/llms.txt` + `/llms-full.txt` expose a compact index and the full public text. `src/proxy.js` + the generated `data/route-manifest.js` (regenerated by `scripts/build-search-index.mjs`; public files and `/llms*.txt` included) reject unknown dynamic paths before streaming, so `/blog/page/*`, `/tags/Web3`, dotted paths such as `/foo.txt`, and arbitrary missing slugs are hard 404s rather than `noindex` 200s.

## Conventions & gotchas

- JS (not TS) throughout; most imports are **relative**, even though `jsconfig.json` defines `@/*` → `./src/*` (the alias is currently unused).
- **Turbopack is required and `next.config.js` is plain** — no `withContentlayer` wrapper, no plugin. `next dev`/`next build` run directly against the app.
- Tailwind is **v4** (`@tailwindcss/postcss` + `@import "tailwindcss"` in `globals.css`) loading a minimal v3-style `tailwind.config.js` via `@config` (typography plugin + `darkMode: ["class"]`). All colors/radii/shadows/motion are tokens in `globals.css` `@theme inline`.
- `/_next/image` responses carry `Content-Disposition: inline` natively via `images.contentDispositionType` in `next.config.js` (Next's optimizer defaults to `attachment`, which makes direct opens download). There is no legacy middleware override and no vercel.json; `src/proxy.js` is the small Node proxy that validates page-like paths, including dotted ones, against the route manifest before rendering (see “Routing overview”).
- Analytics is self-hosted **Umami** (`src/components/umami-analytics.js`, config in `siteMetadata.umami`); it only loads in production, with `strategy="lazyOnload"`. Comments are **Giscus**, split in two: `comments.js` is the lazy shell (`#comments` anchor, `min-h-[320px]` reservation, `IntersectionObserver` with a 600px rootMargin) and `giscus-embed.js` is the widget, loaded via `next/dynamic({ ssr: false })` only when the reader nears it. A third-party iframe on every article was the largest avoidable cost on the article path; measured 0 `giscus-widget` before scrolling, 1 after, 0 requests to giscus.app on load.
- **Prefetching is a budget.** `<Link prefetch={true}>` is reserved for post cards and prev/next; static nav destinations use the default App Shell prefetch and `/about` keeps `true`; tag chips (`tag-chips.js`) and the tag sidebar (`bloglistlayout.js`) are `prefetch={false}` — a page of eight cards used to fire up to 24 tag prefetches for links nobody clicks, competing with the article prefetch that does predict the read.
- `images.minimumCacheTTL` is 31 days: optimized URLs carry a content hash, and Next's 60s default re-runs the optimizer on every repeat view of an unchanged file.
- Search is **server-side full text, rendered in a navbar command palette**. `scripts/build-search-index.mjs` writes `public/search-index.json` with the plain-text body of every post *and* every page (`type: "post" | "page"`, Chinese tag labels kept so 经济/金融 queries hit English tags). `src/app/api/search/route.js` reads that corpus once per process, runs Fuse (title 1, tag labels .8, description .7, body .5; `ignoreLocation`, threshold .32) and answers `{ q, results, took }`; results carry `href`, pre-formatted date/reading time and a highlighted body `snippet`. The index is **never sent to the browser** — the dialog (`src/components/search-dialog.js`, first button in the navbar toolbar) fetches results instead, debounced 160 ms with an `AbortController`, and opens on click, ⌘K/Ctrl+K or `/`. Headless UI `Dialog` (loaded only when search opens) owns Esc, outside-click, focus trap, scroll lock and the inert background; the motion is a CSS fade + 4 px rise on the panel. Minimum query length is 2 characters; responses are `private, no-store`. The old client Fuse store (`use-post-search.js`) and the home/archive search inputs were deleted — do not reintroduce a second search path.
- **Tag hygiene**: `node scripts/check-tags.mjs` (add `--json`) reports unknown tags (which would 404), single-tag posts, tags with fewer than three posts and the full distribution, from `public/search-index.json`. It is deliberately not wired into `package.json` — the publish script deletes `scripts/` apart from the search-index generator, so a shipped `check:tags` script would be a broken command in the template.
- **The lightbox is in-house and wired through CSS classes, not props**: `rehype-figure` tags every post image with `lightbox-image`, `OptimizedHTMLRenderer` preserves that class when swapping in `next/image`, and the root layout mounts `Lightbox` (`lightbox-controller.js`). One delegated `click` listener on `document` opens the viewer — no handler per image, no per-navigation DOM walk. The viewer component (`lightbox-viewer.js`, ~380 lines) is dynamically imported **on intent** (`pointerover`/`focusin`/`touchstart`), so a reader who never opens a photo downloads **0 bytes** of it; it replaces `yet-another-react-lightbox` (removed, −30 KB gz per post route) and keeps the features that library provided: prev/next, wheel/±/double-click zoom, drag pan, pinch, counter, caption, Esc, focus trap, scroll lock, background `inert` — all from `src/lib/overlay.js`. Dropping the `lightbox-image` class anywhere breaks it.
- **Lightbox geometry and paging**: the stage is `flex: 1 1 0; min-height: 0` and the figure fills it 100%, so a 4096 px-tall bitmap is constrained by `max-height: 100%` (it used to overflow and cover the toolbar — the "opens already zoomed" report). The slide list is scoped to the clicked image's `article`/`main`, not the document: React `<Activity>` keeps navigated-away routes mounted, so a document-wide `main img.lightbox-image` query used to page into another article's images. Prev/next is a **pure horizontal slide, with no opacity animation**: a 200%-wide track holds the outgoing and incoming cells, one `translateX` animation moves across the stage (260 ms), then React drops the outgoing cell and the track returns to 100% with no visual jump. The previous version crossfaded two layers, which stacked two semi-transparent bitmaps for ~180 ms and read as a flash — worst when the two aspect ratios differed. The caption sits **between** the stage and the toolbar so it can never cover the controls, and it fades with a keyed `<p>`.
- **Open and close are a centre zoom, not a View Transition and not a FLIP handoff.** `startViewTransition` cost 180-250 ms *before* its update callback on an image-heavy post (it snapshots the page), which is the reported slowness. The viewer animates its own bitmap from `scale(0.92)` to 1 as the scrim fades in (260 ms); closing shrinks it to `scale(0.94)` with opacity 1→0 while the scrim and chrome fade (240 ms), and the unmount waits on the animation's `finished` promise (with a timeout fallback) so a busy main thread cannot drop the first painted frame. FLIP from the thumbnail was tried and dropped: it tied the gesture to a captured rect and needed re-targeting after paging, while the centre zoom is the same for every slide. `prefers-reduced-motion` skips both and closes immediately. Do not reintroduce `startViewTransition` here without re-measuring.
- Dates are formatted with `src/lib/date.js` (Intl, zh-CN long form; Beijing time when a clock time is involved) and sorted with `date-fns` (`compareDesc`). Never reintroduce moment. Reading time uses `readingTimeLabel()` (`约 N 分钟`) and the footer year `yearInBeijing()` via `getSiteYear()`.
- Shiki emits only `--shiki-light`/`--shiki-dark` vars (`defaultColor: false` in the pipeline); the active color is applied by CSS in globals.css.
- `data/.obsidian/` and `.obsidian/` are gitignored and must **never** reach the published template — they can carry plugin credentials (e.g. Livesync).
- `.next`, `.tmp`, and `public/search-index.json` are generated — never edit by hand.

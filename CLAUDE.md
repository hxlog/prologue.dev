# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A content-first personal blog (Chinese, `prologue.dev`) built on **Next.js 16 App Router + Turbopack, React 19, Tailwind CSS v4**, on an **in-repo filesystem content layer** (no Contentlayer). Production is a **fully static export** of this app (Next 16 output: export) served by **Cloudflare Workers Static Assets** (assets-only Worker, no runtime code, $0); see docs/DEPLOY-CLOUDFLARE.md.

It doubles as the **source of truth for a public starter template** — see the "Template publishing" section, which is the least obvious part of this codebase.

## Commands

```bash
corepack enable        # once per machine — makes `yarn` resolve to the pinned Yarn 4
yarn install           # install dependencies (node-modules linker)

yarn dev               # build search index + next dev --turbopack
yarn build             # search index + image variants + OG cards + version.json + next build --turbopack (Vercel path)
yarn start             # serve production build
yarn export            # static-export build into out/ (Cloudflare target; OG cards, version.json, feeds, host files)
node scripts/verify-export.mjs  # structural checks on out/ before deploying
npx wrangler deploy --config wrangler.jsonc  # deploy out/ as an assets-only Worker
yarn lint              # eslint (flat config in eslint.config.mjs)

yarn build:e2e       # testing-API-enabled production build for Playwright
yarn test:e2e        # instant navigation + SEO + overlay e2e

yarn publish           # build the template snapshot locally (dry run — no push)
yarn publish -- --push # force-push template to hxlog/prologue-blog-template
```

CI (`.github/workflows/ci.yml`) runs `lint`, `build`, and the production-mode `e2e` job.

## Package manager

**Yarn 4 (Berry)**, pinned by `packageManager` in `package.json` and driven through Corepack: run `corepack enable` once per machine, after which `yarn` resolves to the pinned release anywhere in this repo. `yarn.lock` is committed; there is no `package-lock.json`. `.yarnrc.yml` sets `nodeLinker: node-modules` — Next.js/Turbopack and Vercel both need a real `node_modules` tree, so Plug'n'Play is not an option here.

CI enables Corepack before every job and installs with `yarn install --immutable`, which fails instead of rewriting `yarn.lock` (the `npm ci` equivalent). `engines.node` is `24.x` (the Vercel-supported LTS line; `engines` overrides the dashboard setting), `.nvmrc` is `24`, and CI uses `24.x`.

Two dependencies are deliberately not on `latest`, both because of peer ranges rather than preference:

- **`eslint` on the latest 9.x** — `eslint-config-next@16` pulls in `eslint-plugin-import`, `eslint-plugin-react` and `eslint-plugin-jsx-a11y`, whose peer ranges stop at `^9`. ESLint 10 is a real peer conflict there (npm fails with `ERESOLVE`), so 9.x is the conflict-free latest.
- **`typescript` on the latest 6.0.x** — `eslint-config-next` imports `typescript-eslint`, which `require`s `typescript` at lint time even in a JavaScript project, so it is a real devDependency (npm used to install it as a transitive peer; Yarn does not). Its peer range is `>=4.8.4 <6.1.0`, and TypeScript 7 is out but unsupported.

Everything else is on `latest` as of the migration. `yarn up -i` is the interactive upgrader; `yarn up tailwindcss @tailwindcss/postcss` picks up the one patch release that Yarn's default 24-hour `npmMinimalAgeGate` (supply-chain quarantine of freshly published versions) held back.

## Content layer

There is **no Contentlayer**. `src/lib/content/` reads `data/content/**` with `fs` and produces the same document shape Contentlayer2 emitted:

- `load.js` — the loader. Reads frontmatter, computes `readingTime`/`headings` eagerly; `body.html` is **lazy and async** (Shiki is the whole cost). `getPosts()`, `getPages()`, `getPost()`, `getPage()`, `getBodyHtml(doc)`, `getAllPostsWithBody()`.
- `pipeline.js` — the one markdown renderer (unified: remark gfm/math/gemoji → rehype katex/slug/figure/mermaid-pre/shiki/stringify). Plugin order and options are copied from the old `contentlayer.config.js` and verified byte-identical against it. **Do not add options to `remarkRehype` or `rehypeStringify`** — Contentlayer called both bare, and raw HTML blocks collapsing to their text content is load-bearing for three posts.
- `slug.js` — the slugger + heading extractor (F2 fix: anchors and ids now come from the same pass).
- `index.js` — the public API, and **the only file carrying `import "server-only"`**. `standalone.js` is the same surface without the guard, for plain `node scripts/…`.

**The exports are functions, not arrays, and the name says so.** `getPosts()` replaces Contentlayer's `allPosts` constant. The markdown is read with `readFileSync`, which no bundler watches, so a module-scope constant freezes at first evaluation and a content edit in `next dev` keeps serving stale HTML. `load.js` therefore checks an mtime+size signature of the tree on each access (~1.2 ms over 64 files vs ~103 ms to re-parse) and re-reads when it changes; the check is skipped entirely under `NODE_ENV=production`. See `current()` in `load.js` for the ENOENT/EBUSY reasoning. Do not "simplify" this back into a constant, and do not cache the returned array across a render.

Frontmatter is validated **loudly**: a mistyped `draft: "false"` (which is what Obsidian's Properties UI writes when the property type is Text) fails the build naming the file and field, where Contentlayer2 warned and silently skipped the document. Pages (`data/content/pages/`) need only `title` and `description`; posts also need `publishDate`. **A page's body is plain markdown and raw HTML in it is dropped, not escaped** — the pipeline calls `remarkRehype`/`rehypeStringify` bare, so an `<img class="...">` in `about.md` disappears. Anything on a page that needs styling, like the author avatar, is a frontmatter field the page template renders (`avatar:`, opt-in); see `docs/CONTENT.md`.

`src/lib/microblog.js` reads the one non-post dataset: `data/microblog.yaml`, a list of `{ date, content, images? }` entries (`images[].desc` is the lightbox caption). It parses with the `yaml` package and returns `getMicroblog()`. Entry ids are **derived, not stored** — `mb-<YYYYMMDD>-<array index>` — so they are stable only as long as the list order is; inserting an entry in the middle renumbers every later one and breaks `/microblog#…` anchors and RSS guids at once. `getMicroblog()` is a function for the same staleness reason as the loader.

`data/links.yaml` (friend links) is read inline by `src/app/links/page.js` with the same parser. `data/static/` no longer exists: the site's static assets are a **real tracked directory** at `public/static/**`, served directly by Next at `/static/*`. It is deliberately not a symlink or junction to a directory under `data/` — Next's static-copy step refuses to copy a directory into itself, which fails the build on Vercel ("Cannot copy '../data/static' to a subdirectory of itself").

`data/sitemetadata.js` and `data/tagLabels.js` are **hand-written** modules, not generated. They are read by *client* components (navbar, footer, the two modals, tag chips), so their values have to be in the JS module graph and shipped to the browser — a browser cannot import markdown, and an `fs` read at render time cannot reach a Client Component either. That is why they are `.js` and why they are committed rather than gitignored.

`data/headerNavLinks.js` is a `.js` file for the same client-component reason.

`data/sitemetadata.js` is the single source for owner/site identity: title, author, description, avatar/cover, email/feed email, GitHub, optional Zhihu, license, feed generator, and the page-level copy under `pages` (archive, microblog, links, ui, llms). Runtime code reads these fields; optional social values such as `zhihu` are rendered only when defined. The public template uses generic values and an empty `zhihu`. Do not reintroduce owner-specific strings into `src/`; add a field to `data/sitemetadata.js` (and the matching `template/data/sitemetadata.js` when it is a starter setting) instead.

## Markdown pipeline & Mermaid

Configured in `src/lib/content/pipeline.js` (remark: gfm, math, gemoji; rehype: katex, slug, custom `rehype-figure`, custom `rehype-mermaid-pre`, shiki, stringify). The custom rehype plugins live in `src/components/`.

`rehype-mermaid-pre` converts ```mermaid code fences into `<pre class="mermaid">` blocks. Mermaid is then rendered **two different ways** depending on the consumer — keep both in sync if you touch either:

- **On the web**: `OptimizedHTMLRenderer` (`src/components/optimized-html-renderer.js`) parses the rendered HTML, routing `<img>` to `next/image` and `<pre class="mermaid">` to the client-side `MermaidBlock` (dynamic-imports `mermaid`, theme-aware, immediate on mount); everything else goes through `dangerouslySetInnerHTML`. `MermaidBlock` **replaces** the `<pre>` with a `div.mermaid`, so a rendered page has 0 fences and 1 SVG — anything asserting on fence count is asserting on what is supposed to be gone.
- **In feeds**: `src/lib/feed/mermaid.js` + `mermaid-shared.mjs` rewrites the same `<pre>` blocks into hosted `mermaid.ink` PNG `<img>` URLs (pako deflate + base64url encoding), since RSS readers strip inline SVG.

**The web renderer forces `look: "classic"`, and that is a design requirement, not a preference.** Mermaid 12 changed the flowchart default to `look: "neo"`, which paints a drop-shadow halo `filter: drop-shadow(1px 2px 2px rgba(185,185,185,1))` plus a gradient stroke around *every* node and cluster. Under this site's flat hairline surfaces that reads as a second, duplicated elevation — the "why is the mermaid diagram dirtier than on GitHub" report. `MermaidBlock` initializes with `look: "classic"` (the flat render GitHub shows), passes `--font-sans` in as `themeVariables.fontFamily` so diagrams use the site's type stack instead of Trebuchet MS, and `globals.css` keeps an `!important` `filter: none` reset over `.mermaid svg [data-look="neo"]` as a version-proof backstop. Measured after the change: 0 elements with a computed `filter` across three diagrams on `/blog/evaluating-ai-data-labeling-accuracy`, versus every node rect before. Do not "restore" the neo look without a screenshot comparison against the flat surfaces.

## Feeds (RSS / Atom / JSON)

Routes: `src/app/rss`, `src/app/atomfeed`, `src/app/jsonfeed`. All three call `createFeed()` in `src/lib/feed/build-feed.js`, which builds a single `Feed` instance; each route only picks the serializer (`rss2`/`atom1`/`json1`). Per-item HTML is produced by `buildFeedContent()` in `src/lib/feed/content.js`: it promotes block math, then uses the feed-only helpers in `src/lib/feed/html.js` to split paragraphs that wrap a `<figure>`, strip every inline `style`, replace native MathML with readable TeX `<code>` fallbacks, and escape bare ampersands before URLs are absolutized and images normalized. Article pages deliberately keep their MathML and Shiki styles; only feeds are downgraded. Categories are emitted as Atom `term`/`label`/`scheme` plus RSS/JSON labels, and `coverImageUrl()` supplies a lead image for every item (falling back to `/og`). Format-specific fixes the `feed` library can't express (Atom `xml:lang`, a Folo-readable feed `<image>` as namespaced foreign markup plus enclosure-MIME normalisation, RSS guid permalink plus `dc:creator` as the only author, JSON Feed 1.1 language/favicon/authors and per-item `image`) live in `src/lib/feed/finalize.js` — note `imageByUrl()` is a function, not a module constant, for the same staleness reason as the loader. URL helpers in `src/lib/feed/urls.js` derive absolute URLs from `siteMetadata.siteUrl`; `coverImageUrl()` falls back to the `/og` generator when a post has no `image`. `/microblog/rss` reuses `finalizeRss()` so its guid/author behaviour matches the main RSS feed.

Feed XML is produced by `getFeedXml(format)` in `src/lib/feed/cached.js`, where the work is split at the cache boundary:

- **`getFeedItems()` owns the expensive half.** It renders every post body (Shiki) once per build and is shared by the three feed formats; `src/lib/content/cached.js` plus a production-only module memo in `src/lib/feed/cached.js` keep that single build-time pass. Cache Components is gone (static export), so there is no cacheLife/cacheTag any more.
- **`getFeedXml()` only assembles and serialises** (6–19 ms per format). The routes are plain static handlers (`export const dynamic = "force-static"`) that run once at build and emit extensionless files (`out/rss`, `out/atomfeed`, `out/jsonfeed`); `out/_headers` gives them the correct Content-Type and Cache-Control.
- **`<lastBuildDate>` is content-derived** — `max(lastmod || publishDate)`, never a render-time clock read. Identical content must produce identical bytes so a rebuild does not churn the feeds.
All four feeds are served with `public, max-age=600, stale-while-revalidate=86400` from `out/_headers`; content changes only when a build runs and a new Worker asset version is deployed, so there is no purge step and no ISR clock to keep in sync. Feed HTML also drops Shiki's `<span>` shells (`unwrapSpans()` in `src/lib/feed/html.js`) — the colour CSS is already stripped, so the wrappers were pure weight. Do **not** shrink the feed by summarising posts; the full text is the contract.

## Template publishing (important)

This repo is mirrored to a public template (`hxlog/prologue-blog-template`) **without the author's posts, maintainer-only files, or personal assets**. On every push to `master`, `.github/workflows/publish-template.yml` runs `yarn publish`, which executes `scripts/publish-template.mjs`. That script:

1. Creates a detached git worktree of `HEAD`.
2. `applyStarterTemplate()` deletes maintainer-only paths (`template/`, `docs/`, `.idea/`, `scripts/`, `Dockerfile`, `.dockerignore`, `fly.toml`, the publish + Fly deploy + monitor workflows), wipes `data/content/*` and `public/static`, then copies the starter overrides from `template/`.
3. Force-pushes the snapshot to the template repo (auth via `TEMPLATE_REPO_TOKEN` secret, falling back to `gh auth token`).

**Implications when editing:**
- The `template/` directory is the starter's overrides — not used by this site, but *is* what template users receive. Edit it when you intend to change the template's default content/assets.
- Anything new added for the template must be placed under `template/` (or whitelisted in `applyStarterTemplate`), or it won't ship. `ensureTemplateInputs()` asserts the required ones exist, so a missing file fails the publish rather than shipping a broken clone.
- Template-critical files that live in `src/` or `scripts/` are copied explicitly by `applyStarterTemplate`: `scripts/build-search-index.mjs`, `scripts/build-image-variants.mjs`, `scripts/build-og-images.mjs`, `scripts/build-version.mjs`, `scripts/next-export.mjs` and `scripts/build-cf-assets.mjs` — the shipped `dev`/`build`/`export` scripts invoke them. **Anything the shipped scripts invoke must be in that list**, or a fresh clone fails on its first command. `docs/readme/*.webp` is copied too, because the template README embeds the screenshots.
- `template/data/{microblog.yaml,links.yaml,sitemetadata.js,headerNavLinks.js,tagLabels.js}` and `template/public/static/` are required inputs; five `src/` files import the two `.js` data modules, so a template without them does not build.
- Locally, `yarn publish` builds and inspects the snapshot under `.tmp/` (gitignored) and stops; `yarn publish -- --push` is what force-pushes. CI passes `--push`.

## Deployment (Cloudflare Workers Static Assets)

Production is a **static export on Cloudflare**: yarn export writes out/, and wrangler deploy uploads it as an **assets-only Worker** (no main, no user code, no origin, no tunnel). Static asset requests are free and unlimited on the Free plan; custom domains are included. `prologue.dev` and `www.prologue.dev` are the only public hostnames (www 301s to apex at the zone edge). Full runbook: docs/DEPLOY-CLOUDFLARE.md.

**Vercel is supported as an equivalent alternate target**: `yarn build` includes `build-og-images.mjs` and `build-version.mjs` (so `/og/*.png` and `/version.json` exist on Vercel), and the published template ships both deployment paths plus one-click buttons. See docs/DEPLOY-VERCEL.md. The published template keeps `wrangler.jsonc`, `scripts/next-export.mjs`, `scripts/build-cf-assets.mjs`, `export`/`deploy:cf` scripts and `docs/readme/` screenshots (publish-template copies the latter so its README images resolve).

- **Why static export.** Next 16 rejects Cache Components/PPR together with output: "export" ("PPR cannot be enabled in export mode"), so cacheComponents, partialPrefetching, use cache, cacheLife, cacheTag, instant and ensureStatic are **removed from this codebase**. Every route is prerendered at build; client navigation uses the generated RSC .txt payloads; React 19 ViewTransition still animates (verified).
- **Build pipeline.** scripts/build-search-index.mjs (full + lite search corpora, image sizes, route manifest) → scripts/build-image-variants.mjs (AVIF-first + WebP fallback multi-width variants) → scripts/build-og-images.mjs (70 static cards, local font subsets) → scripts/build-version.mjs (public/version.json for stale-tab reloads) → scripts/next-export.mjs (next build with NEXT_EXPORT=1) → scripts/build-cf-assets.mjs (out/_headers, out/_redirects, flattened RSC payload paths).
- **Host semantics.** wrangler.jsonc is assets-only with html_handling auto-trailing-slash (extensionless routes → *.html) and not_found_handling 404-page (this replaces the deleted src/proxy.js hard-404). out/_headers (17 rules) carries a baseline security header set (nosniff, Referrer-Policy, Permissions-Policy, X-Frame-Options, CSP frame-ancestors), feed Content-Type/caching, `/version.json` must-revalidate, immutable hashed assets and max-age=0, must-revalidate HTML; content-hashed /_next/static, /static/variants|source|opt and /og are immutable.
- **What used to be request-time is now build-time.** /og cards (route deleted; src/lib/og/{keys,render}.js + scripts/build-og-images.mjs, URL contract /og/<key>.png?v=5), /api/search (route deleted; browser Fuse over public/search-index.json, lite-first + idle preload), feeds/llms (static route handlers with export const dynamic = "force-static"). No server runtime: no runtime segment config, no proxy/middleware, no headers()/redirects() (zone rules instead).
- **Zone.** No Cache Rules: the Worker asset version is the cache identity, _headers is the policy, and the deploy workflow purges the edge cache after each deploy. Keep Rocket Loader **off**, TLS 1.3 / HSTS / Always Use HTTPS / Brotli / HTTP3 / 0-RTT on. **Speed Brain / Speculation Rules are OFF** (they duplicate Next prefetch and previously made `/cdn-cgi/speculation` a text/html 404 on the Worker); Early Hints is OFF; **Cloudflare Workers Builds trigger is deleted** (GitHub Actions is the single CI/CD path). A zone Response Header Transform Rule adds the missing `charset=utf-8` to extensionless HTML paths, excluding `/static/`, `/og/`, `/cdn-cgi/` and the four extensionless feeds. Managed robots stays on (it prepends the same 3,153-byte block production always served). Do not touch MX/SPF/DKIM/DMARC.
- **Static correctness.** Every page awaits its build-time data directly: no server Suspense/streaming fallbacks, no `loading.js`. The real content is in the exported HTML (verified with JavaScript disabled on home, post, tag and markdown pages), which is also the crawler/no-JS contract. Do **not** re-add server Suspense fallbacks or `prefetch={true}`: in the static export a completed full prefetch can poison the client router cache (dead clicks), and Suspense fallbacks only hide content behind a JS reveal. Short client-side waits use `useLinkStatus`-based `.link-pending` hints (fixed size, no layout shift). `public/version.json` + the client `VersionGuard` reload an open tab when a newer build is deployed, bounding version skew between HTML and hashed chunks.
- **Dual deploy**: the repo root README (zh) + README.en.md (en) documents both Cloudflare and Vercel; one-click buttons point at the template repository. The template also ships a Cloudflare config so `yarn export` + `yarn deploy:cf` works from a clone.
- **Fly.io is decommissioned** (2026-11-24): the app, Machines, builder app, cloudflared tunnel, Fly DNS records and the old __uptime Worker were deleted after the Cloudflare cutover; `Dockerfile`, `fly.toml`, `deploy-fly.yml` and `monitor.yml` are removed from the repo. Rollback is now a Cloudflare-side DNS/rule operation, not a Fly redeploy.

## Design system

Semantic tokens live in `src/app/globals.css` under `@theme inline`, mapped to CSS variables that flip under `.dark`.

**Brand primitives: lavender `#b5b5e5`, pink `#e6c9d9`, warm stone `#a8a29e`** (`--color-brand-lavender` / `-pink` / `-stone`) are the historical source swatches and carry no semantics. The pastels actually painted are `--accent-pastel #c9cdf5` / `--secondary-pastel #f7d4e6` / `--sky #b4e0ec`. None of them are consumed for text; everything reads a semantic token.

**v3 "ice lavender" palette.** v2 ("cool paper") moved the neutrals from warm stone to cool slate; v3 pushes the accent one more step towards light, because the purple still read as heavy:

- **Light mode**: background `#f7f8fc`, ink `#2f3446` (11.6:1), surfaces `#ffffff` / `#f1f3fa` / `#e5e8f3`, `--muted #5d6579` (5.49:1), `--faint #767e92` (3.83:1 — allowed below AA because it only carries metadata that appears elsewhere). Accent `#6a6fcd` (**4.15:1** on the page, 4.40:1 on a white card), secondary `#b85680` (4.23:1). **The accent is deliberately below AA for small text.** It is used for **chrome only** — eyebrows, the active nav pill, card-title hover, border and gradient tints — where a miss costs nothing; the brief asked for a visibly lighter, cooler lavender and this is the approved trade. Two things never use it: a *fill carrying a label* (buttons: `--accent-strong`, 5.35:1 with white) and *body copy* (prose links and inline code: 5.04:1 / 5.01:1 on the page, because 18px regular is not "large" per WCAG). Hover on a body link goes lighter, not darker, matching the rest of the site.
- **Dark mode**: background `#14161d`, surfaces `#1c1f28` / `#242832` / `#2f3441`, ink `#eef0f7` (15.9:1), `--muted #b3b8c6` (9.1:1), `--faint #979db0` (6.7:1). Accent `#ccd0f8`, secondary `#f4cede`. `--border-strong` is `0.14`, not `0.18`: the brighter hairline was the second half of the "dark hover is too white" report.
- **A fourth hue, sky `#b4e0ec`** (`--sky`), is allowed ONLY inside gradients and the cursor glow. It never carries text or a control, so it cannot fail contrast.
- `--accent-strong` is the *darker* ink in light mode and the *lighter* pastel in dark mode: "strong" means "more contrast against the current background".
- `--on-accent` is white in light mode and `#1b1d26` in dark, because white on pale lavender fails in dark mode.
- Gradients: `--gradient-brand` is the **fill**, and it is now **three stops** (lavender → `#dff0f9` sky → pink) so a brand rule reads as a gradient rather than a two-colour ramp; `--gradient-brand-text` is the **text** gradient (light mode uses the inks). `bg-clip-text` must use `--gradient-brand-text` or the headline washes out. **The homepage hero has no colour wash**: it sits directly on `--background` with no overlay layer, so light and dark read as one flat field behind the headline (the old `.hero-aurora` gradient and `--gradient-aurora` token are gone — do not reintroduce a tinted layer behind the opening copy).

One ladder covers type (`--text-caption/sm/base/lead/title/h2/h1/display`, each with its own line-height), radii (`control/card/panel/pill`), containers (`page/archive/read`), shadows (`card/card-hover/pop`, all tinted by `--shadow-tint`) and motion (`--ease-out-expo`, `--duration-instant/fast/base/enter/slow`). Prefer these over arbitrary values; a new arbitrary radius or duration should be a token.

The v3-style `tailwind.config.js` (loaded via `@config`) holds only `darkMode: ["class"]` + the typography plugin.

**Fonts: system only — the site makes ZERO font requests.** There is no `next/font` import anywhere. `--font-sans` is the latin faces followed by the platform CJK stack (PingFang SC / Microsoft YaHei / Noto Sans CJK), and it is the *only* family: `--font-serif` no longer exists and the three `font-serif` call sites (home lead, page description, post description) were folded into it. `--font-mono` is the platform mono (ui-monospace / Menlo / Consolas) and is used only by code content and `.copy-field`.

Two rounds got here, both by measurement. First the two `Noto_*_SC` families: 101 unicode-range slices each, **33 woff2 / 1.99 MB** on one Chinese article, and because text paints with the fallback and repaints as slices arrive, every arrival was a new LCP candidate (p75 13.2 s on a 196 KB page). Then the last latin mono (`JetBrains_Mono`, 40 KB) went too — `display: "swap"` still painted code blocks in the fallback first and swapped them, the same mechanism, on every code-heavy article. **Do not reintroduce a webfont without re-measuring LCP — the swap repaint is the mechanism, not the byte count.**

Formulas are **native MathML**: `rehype-katex` runs with `output: "mathml"`, the post route no longer imports `katex.min.css`, and `src/lib/feed/content.js` no longer strips a KaTeX presentation layer (there is none). Measured on a 10-formula post: **0 font requests** and 0 `span.katex-html` nodes, versus 1-3 woff2 / 10-25 KB before. That was the last webfont on the site, so "zero font requests" is now literally true rather than "except math". The tradeoff is deliberate: MathML is set by the platform math font, so a formula's glyphs are no longer identical across OSes. The alternative — keeping KaTeX — costs a font fetch per math article plus a katex stylesheet in every article's critical CSS. If formula fidelity ever becomes a requirement again, this is the exact line to revert (plugin option + `import "katex/dist/katex.min.css"` in the post route) and the numbers above are the baseline to re-measure against.

**Typography overrides must map the whole `--tw-prose-*` family.** `@tailwindcss/typography` only swaps its defaults under `.prose-invert`, and this site toggles dark mode with a class on `<html>` — so leaving the defaults in place made `--tw-prose-headings` (its `#111827`) paint every H1/H2 near-black on the dark background. The `.prose` block in `globals.css` now points headings, bold, links, quotes, captions, bullets, code, table borders and their `-invert` counterparts at semantic tokens. Add a new prose rule *after* the token-mapping block, not before.

**No animation library.** `framer-motion` is not a dependency. The root `<MotionConfig reducedMotion="user">` alone pulled it into every route's shared chunk to honour an OS preference; reduced motion is handled in CSS, the tab-panel cascade is the `.reveal-rise` class, and the TOC marker is `.toc-pill` (drawn inside the active row, because rows wrap to different heights and a single sliding pill would need layout measurement).

**Component classes** live in a `@layer components` block in `globals.css` so markup reads as structure, not as twenty utilities: `.shell` (page container), `.sticky-below-nav` (sidebar `top` that clears `--nav-height`), `.skip-link`, `.btn` / `.btn-primary` / `.btn-ghost` / `.btn-icon`, `.input`, `.nav-item` (a **pill**; active state via `[data-active]` / `[aria-selected]` / `[aria-current]`), `.card` / `.card-interactive` / `.card-spotlight`, `.chip` / `.chip-more`, `.eyebrow` / `.section-label`, `.link`, `.text-gradient`, `.glass-header`, `.reveal-rise`, `.toc-pill`, `.modal-panel`, `.copy-field`.

Two shape decisions are deliberate. **Cards are flat at rest** — the elevation is an inset hairline ring (`--shadow-card: inset 0 0 0 1px var(--border)`), so nothing is lifted until the pointer arrives. Hover is a 2px lift plus **one twin-outline system**: `.card-spotlight::before` paints a 1px conic rim whose three colour sectors rotate to the pointer, `.card-spotlight::after` paints a soft pointer-tracked glow, and the second outline is a 1px inset hairline (the `inset` layer of `--glow-shadow`) drawn over the neutral one.

`conic-gradient` in three 120° sectors — sky, lavender, pink — with 6 % blends, shown only as its 1px border by masking the content box and the full box and excluding the first from the second. The `from` angle is `--spot-ang + 90deg`, so the first sector boundary lands at the pointer and the hues rotate around the card as the cursor moves. Measured on a text-free 397×208 probe with the production CSS: pointer at the centre (`from 90deg`) puts **pink on the top edge, sky on the right and bottom edges, lavender on the left**; pointer at the top-left (`from -61deg`) puts **sky on top, lavender on the right, pink on the bottom-left**. All three hues are on the rim at once, at 0.6 (light) / 0.35 (dark) alpha of saturated pastels — pale hues at high alpha composite to "tinted paper", while a saturated one at low alpha keeps real chroma without darkening the card.

The glow is two concentric radials at `--spot-x` / `--spot-y` (lavender core, sky halo), light 0.24 / 0.12 and dark 0.07 / 0.033. It is deliberately not a third hue: the rim already carries all three, and a tri-hue glow blends to lavender under the text. Measured with the probe: light hover **mean L 0.967 against 0.999 at rest** (max C 0.090, 24 % of the card chromatic — still "very light"), dark hover **mean L 0.275 against 0.241** (+0.034, the faint-halo target), and a real card's title computes the same colour hovered and at rest in both themes.

This replaced the earlier conic "aurora" ring and the v4 band wash + 1px rim + three-blob glow — both read as one tinted surface rather than as three colours, and the twin-outline + glow is the version that keeps the card white. Removed with them: `.card-ring` (and its `<span>` in `card.js` / `friendlinks.js`), `--aurora-*` (triplets and ellipse radii), `--ring-*`, `--sheen-hi`, the `spot-breathe` keyframes and `--spot-a`. The `--glow-*` tokens are RGB **triplets** now so one triplet powers the rim, the hairline and the glow at three alphas.

**Tag pills reuse the card rim in a cheaper form ("stardust").** A 24px pill cannot carry the twin-outline + glow pair, so at rest `.chip` is a 6 % three-hue wash plus a 1px lavender hairline (`--chip-wash-a` / `--chip-hairline-a`); on hover a 1px conic rim (`--chip-ring-a` 0.9 light / 0.58 dark — a 1px line needs more saturation than a card-wide rim) spins on the registered `--chip-ang` for 5.5 s, two 1px stars inside the pill twinkle at 1.7 s, and the label steps to `--accent-strong` (5.04:1 light, 13.6:1 dark). The old 20–24 % `--wash-*` fill is gone: three hues spread across ~48px do not separate, so the pill read as one dirty block. The stars paint at `z-index: -1` under `isolation` — above the wash, never over the glyphs; `prefers-reduced-motion` stops the spin and the twinkle and keeps the static ring. Specimen in `/ui` section 05. **`.eyebrow` is not uppercase and is not letter-spaced** — the labels are Chinese, where both only hurt legibility, and a tracked all-caps eyebrow over every heading is the most templated-looking device on the web right now.

**The living UI standard is a route, not a document.** `/ui` (`src/app/ui/page.js`) renders the palette, type ladder, radii, shadows, motion tokens, component gallery and the live card-hover demo. It ships no colour or size of its own: `src/lib/css-probe.js` walks the stylesheets, rebuilds `:root` and `.dark` as two self-contained scopes on the page, and reads every value with `getComputedStyle`, so editing `globals.css` updates the page with no second edit and the light/dark panels stay correct even while the page itself is in the other theme. The only per-token maintenance is one row in the page's `GROUPS` arrays (token name + purpose); a deleted token shows as "读取中…" instead of silently drifting. The route folder is lowercase `ui`, so the path is `/ui` — do not add a case-only `/UI → /ui` redirect, because Next matches redirect sources case-insensitively, so the rule also matches `/ui` and loops (`ERR_TOO_MANY_REDIRECTS`). Keep new components in that gallery: the rule is "specimen first, then the real route".

**Post images carry their real intrinsic size.** `rehype-figure` looks the width/height up in the build-generated `data/image-sizes.js` (written by `scripts/build-search-index.mjs`) — never with `sharp` at render time, because a `process.cwd()` path is invisible to `@vercel/nft` and used to drag all 27 MB of `public/static` into every function. It writes `width`/`height` onto the `<img>`; `OptimizedHTMLRenderer` passes them to `next/image`. This used to be hard-coded `1920×1080` for every image, so a 4:3 screenshot reserved a 16:9 box and the article reflowed as the bitmap arrived (measured 639×360 → 639×510 mid-scroll). The **first** body image additionally gets `loading="eager"`, and `fetchPriority="high"` only when the file is under 400 KB — a 4.7 MB animated chart as the eager high-priority candidate was a multi-second LCP. Everything below stays lazy. If a file cannot be read, the attributes are simply omitted and the browser falls back to its own behaviour — this is an enhancement, never a build gate.

**Pointer-tracked cards** — `<Spotlight />` mounted once in `layout.js`, `spotlight.js`. One delegated `pointermove` listener (not one per card) writes `--spot-x` / `--spot-y` (percentages) and `--spot-ang` (degrees from the card centre) onto the hovered `.card-spotlight`, and the CSS does the rest: `.card-interactive:hover::before, .card-interactive:hover::after { opacity: 1 }` reveals the rim and the glow at the values the script last wrote. The listener updates on **every** move inside a card (an early `card === current` guard made the decoration freeze where the pointer crossed the edge — that was the reported "it doesn't follow"), coalesces writes into one `requestAnimationFrame`, and caches the card rect until scroll/resize, since `getBoundingClientRect()` per move forces a layout read. Two `@property` registrations (`--spot-x` / `--spot-y` as `<percentage>`, both `inherits: true`) make the glow **ease** to the pointer (140 ms linear) instead of teleporting; the transition is declared on `.card-spotlight::after`, where the values are consumed. `--spot-ang` is deliberately **not** registered: a conic gradient is 360°-periodic, so easing an angle across the ±180° wrap would spin the rim a whole turn. **The registrations must stay outside `@layer components`; a registered declaration inside a layer is not emitted.** Both pseudo-element layers are `z-index: -1` under `isolation: isolate` on the card (above its background, below its text, and *below* the title's `after:inset-0` stretched link — do not give children `position: relative`, it shrinks the click target to the title). `prefers-reduced-motion` needs no rule here: the angle is instant and the glow is a 140 ms property transition on a 0.24-alpha tint. On `(hover: none), (pointer: coarse)` a static 0.55 rim / 0.18 glow is always on (M2); it is CSS-only, so touch gets the same language without a sticky hover state.

**Do not write `-webkit-backdrop-filter` by hand.** Lightning CSS drops the standard `backdrop-filter` when the prefixed form is also present in the source, which silently killed the sticky navbar's blur. Declare only `backdrop-filter`; the prefix is emitted automatically.

**Theme toggle**: `themeswitch.js` wraps the swap in `document.startViewTransition` with a circular `clip-path` reveal (0.618 s) and adds `.theme-vt` for its duration. `clip-path` is not composited, so the smoothness comes from making the reveal the *only* animation running: `html.theme-vt * { transition: none !important }` suppresses every Tailwind `transition-colors`/`transition-all`, which would otherwise crossfade the same theme tokens underneath it. The block also drops the sticky navbar's `backdrop-filter`. `.theme-vt` is removed in `.then(ok, err)` (not `.finally()`-style success-only) so a rejected transition cannot leave it stuck and freeze every transition site-wide. Measured via `document.getAnimations()`: 0 CSSTransitions mid-reveal with the rule, 561 without.

**Route transitions**: every page wraps its content in `<RouteTransition>` (`src/components/route-transition.js`), a `react` `<ViewTransition exit="page-exit" enter="page-enter-fade" default="none">`. **Both halves are named, and both are animated from the view-transition snapshots, not from the live DOM.** That split is the point: an enter animation on the live tree only runs if React unmounts and remounts the element, and React reuses a node of the same type in the same position — so an exit can run with no matching entrance. A `::view-transition-new` snapshot is created for every transition that produces new content, so that half cannot be skipped. `.page-enter` remains, but as the **first-paint** fade only (a first paint is not a Transition and gets no snapshot); it is also what `PageTransition` emits, and `/blog/[...slug]/page.js` uses the class directly.

Timings are deliberately unequal — `::view-transition-old(.page-exit)` runs `page-fade` **150 ms** reversed, `::view-transition-new(.page-enter-fade)` runs `page-enter-snapshot` (opacity + a 6 px rise) for **260 ms**. Equal durations put both layers at ~50 % opacity at the midpoint, which reads as a wash; the shorter exit makes it a handoff. The 6 px transform is safe **only** on a snapshot pseudo-element — a transform on real DOM creates a containing block and would break `position: sticky` descendants (the homepage's pinned search bar), which is why `PageTransition` stays opacity-only.

CSS lives in `globals.css` next to the theme block. Two details there are load-bearing: `::view-transition { pointer-events: none }` (the snapshot overlays the live page and would eat the reader's next click), and `html:not(.theme-vt)::view-transition-old(root) { animation: none }` — the UA cross-fades the root on *every* view transition, which double-animates a route change; the theme toggle has its own root rule and so is excluded rather than overridden. The navbar and footer sit in `layout.js` *outside* `<main>`, so they are outside every page snapshot and hold still while the content crossfades — the nextjs.org arrangement. Measured with `document.getAnimations()` on `/blog` → post: one `page-fade` at 150 ms on `::view-transition-old`, one `page-enter-snapshot` at 260 ms on `::view-transition-new`, no `old(root)` fade.

**There is deliberately no `loading.js`.** A static export writes the HTML once; a loading boundary can only hide the real content in a `<template>`/hidden div and show a skeleton until client JS runs. Removing the PPR-era server Suspense wrappers made every page's HTML contain the full content (verified with JavaScript disabled), which is the crawler/no-JS contract and also removes the "layout rendered but the article stays loading" failure mode. For genuinely client-side waits the `.link-pending` hint (useLinkStatus) is the intentional UI; dynamic-route prefetch is not enabled (no loading boundary), so a click fetches the small RSC payload and renders. Do not re-add `loading.js` or server Suspense fallbacks without re-measuring both JS-on and JS-off.

Tags: canonical slugs are English (15-tag taxonomy), Chinese display labels live in `data/tagLabels.js`. Tag URLs are `/tags/<EnglishSlug>`. Unknown tags (including the old `/tags/Web3`) are rejected by the generated proxy allowlist and return a hard 404; there are no legacy tag redirects.

## Rendering model (static export)

The app is built as a **static export**: next build runs every page's server components once in Node, then writes HTML plus one RSC payload per route. Nothing renders at request time.

- **Every route is prerendered.** The three param routes (/[...slug], /blog/[...slug], /tags/[...slug]) use generateStaticParams(); the build table shows ○/● only. src/lib/content/cached.js keeps a production-only module memo so each post body (Shiki) is rendered once and shared by the page, the feeds and the search index; in development the memo is off so markdown edits reload through the loader's mtime signature.
- **Data is awaited at build, not suspended.** Pages await their content directly. There are no server Suspense fallbacks and no loading.js: in an export those can only hide the real article behind a skeleton/template until client JS replaces it (verified: with JS disabled the page was a skeleton before this cleanup; now home/post/tag/markdown HTML contains the full content). Client-only lazy modules (comments, search panel, modals, lightbox, mermaid) still load on demand.
- **Client navigation.** next/link uses the default prefetch strategy; the router fetches the generated .txt RSC payloads from the same static host; SPA navigation and history.back() work unchanged. **Never set prefetch={true}:** a completed full prefetch in the static export can poison the client router cache and make clicks do nothing (see card/about regressions). Short waits are shown with the fixed-size useLinkStatus .link-pending hint.
- **Versioning.** scripts/build-version.mjs writes public/version.json before every build; VersionGuard re-fetches it on focus/visibility/pageshow and reloads when a newer build is deployed, bounding Cloudflare version-skew between an old tab's HTML and new hashed chunks. staleTimes.static is 60s so a stale client router entry cannot survive long.
- **No request-time APIs.** proxy.js, headers(), redirects(), cookies(), ISR and Server Actions are unavailable/unsupported in export mode. Path validation is the host's 404-page handling; www → apex is a zone redirect rule.
- **Clock reads happen at build.** getSiteYear() / getRotationOffset() call the clock during the build; content updates ship a new build (and a new deployment version).

## Open Graph card

OG cards are **build-time PNGs**, not a route: scripts/build-og-images.mjs renders 70 cards (50 cover-less posts + 15 tags + about/microblog/links/ui + default) with next/og in Node into public/og/<key>.png, and src/lib/og/keys.js is the single URL/key/version source used by metadata, feeds, JSON-LD and the sitemap. URL contract: /og/<key>.png?v=5 (bump OG_IMAGE_VERSION when the card design or its text changes; there is no dynamic /og?... route any more, old query URLs are 404).

- The rendering code lives in src/lib/og/render.js (Satori-safe primitives only: flexbox, gradients, borders; no grid, no filter: blur), and the palette is hard-coded there because Satori cannot read CSS custom properties.
- assets/og/ holds three Noto Sans SC subset TTFs, a glyphs.json coverage table and a pre-scaled avatar-152.png, all committed and generated by scripts/build-og-font.mjs. Everything is local (no network at build once the subset covers the drawn glyphs); a glyph miss warns and falls back to a per-card Google subset. New title glyphs: rerun build-og-font.mjs, then build-og-images.mjs --force.
- The card visual language ("星屑边": pastel blooms, 2px tri-hue rim, white inset card, stardust tag chips) is unchanged from the request-time route it replaced; the generated PNGs are byte-identical to the old dynamic output for the same input.

## Routing overview

- `/` — home (`src/app/page.js`): featured grid + Latest/top-tag tabs (client-side `Articles`, load-more in batches of 8) + about/microblog sidebar (the terminal / 随想 block is gone). Site-wide search is the navbar dialog, not a home tab.
- `/blog` — archive with tag sidebar and load-more (numbered pagination removed; old `/blog/page/*` paths fall through the proxy allowlist and return 404). Search is the navbar dialog.
- `/blog/[...slug]` — a post. Matches via `post.slugAsParams` against `getPosts()`; includes related posts (`lib/related.js`: tag overlap + recency, excludes prev/next) and a CSS scroll-driven reading-progress bar. The right rail pins the **outline**, not the author card: `AboutMe` sits in normal flow so it scrolls up and away, and `.toc-panel` is the sticky element (a direct child of the `aside`, because the grid row is full article height — nested one level deeper its sticky range would end at the card's bottom). `.toc-panel` also caps itself at `100dvh - nav` with internal scroll, since a sticky box taller than the viewport can never reveal its own bottom.
- `/[...slug]` — markdown pages (e.g. `/about`, plain markdown, no JSX). Matches via `getPages()`. Pages with `portfolio: true` in frontmatter also render the GitHub project block after the body and before the comments. Because that block is a component and not markdown, the page outline appends a synthetic `开源项目` entry pointing at its `portfolio-title` heading (`scroll-offset` keeps the jump clear of the navbar).
- `/tags/[...slug]` — tag pages, **statically prerendered** via `generateStaticParams` from `lib/tag-counts.js`; same cards and load-more as `/blog`. `getTagCounts()`/`getSortedTags()` are functions, not constants, for the same staleness reason as the loader.
